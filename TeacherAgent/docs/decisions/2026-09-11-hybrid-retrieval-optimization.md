# 决策记录：混合检索通道的两个缺陷与一个排序问题

- 日期：2026-09-11
- 状态：三项**均已实施**（2026-09-11）；实测前后对照见文末「实施结果」
- 触发来源：工作项 E 的检索质量评测（`experiments/hybrid_retrieval/`，规格见 `论文v3-待实现工作交付规格.md`）
- 实测归档：`benchmark-results/20260911-000900-hybrid-retrieval-100q/`、`experiments/hybrid_retrieval/work/diag_out.jsonl`

## 背景

为交付规格工作项 E，搭了一套两形态（裸词 / 自然问句）的检索质量评测脚手架，三配置
（纯 BM25 / 纯稠密 / BM25+Dense+RRF）全部走 Rust 生产实现。跑通后发现倒排通道有两处
真实缺陷，融合层还有一处排序偏置。本文记录现象、根因、实测与处置。

裸词形态的整体结果（release，每配置 3000 样本）：

| 配置 | Hit@3 | Hit@5 | MRR | NDCG@5 |
|:---|:---|:---|:---|:---|
| 纯 BM25 | 0.39 | 0.39 | 0.390 | 0.327 |
| 纯稠密 | 0.64 | 0.66 | 0.583 | 0.509 |
| 混合（RRF） | **0.89** | **0.91** | **0.748** | **0.728** |

分来源看更能说明设计意图：混合检索同时对 knowledge_node 金标拿到 0.865、对
private_chunk 金标拿到 0.962，而稠密对片段恒为 0、BM25 对节点仅 0.189——融合拿到了
两通道的并集。时延：BM25 均值 0.12 ms、稠密 2.43 ms、混合 2.60 ms（融合层约 +0.1 ms）。

> 注意：该题集的 gold set 为**机器标注**（目标词取自语料本身、gold = 包含该词的
> 全部实体），非规格要求的两位评审独立标注，指标系统性偏高。归档 `run_manifest.json`
> 的 `caveats` 已记录。上述数字只用于比较配置间差异与暴露实现缺陷，**不得作为论文的
> 检索质量结论**。

## 缺陷一：FTS5 外部内容表不索引"迁移前已存在"的行（已实施）

### 现象与根因

迁移 `0016_private_chunks_fts.sql` 建立了 FTS5 外部内容表与三个同步触发器，但触发器
只对**迁移之后**发生的 INSERT/UPDATE/DELETE 生效。对升级前就有私有文档的老库，倒排
索引是空的。

更隐蔽的是所有既有探针都会说"正常"：

| 探针 | 索引全空时的表现 | 实测 |
|:---|:---|:---|
| `COUNT(*) FROM private_document_chunks_fts` | 读穿主表，返回正常行数（50） | 骗人 |
| `'integrity-check'` 命令 | 不报错 | 骗人 |
| 真实 `MATCH` 查询 | 返回 0 条 | 可信 |

后果是混合检索**静默退化**为纯稠密：私有资料片段完全检索不到，而日志与诊断显示一切正常。
线上库 `user_version` 仍为 14，尚未触发该路径。

### 处置

1. **回填迁移**（新增 `0018_private_chunks_fts_rebuild.sql`）：显式执行一次
   `INSERT INTO private_document_chunks_fts(private_document_chunks_fts) VALUES('rebuild')`。
   不能改 0016 —— 已应用过 0016 的库不会重跑该文件。`database.rs` 已注册（`user_version` → 18），
   `lib.rs` / `sync/db.rs` / `database.rs` 的版本与迁移清单断言同步更新。
2. **可信探针** `fts_index_complete`（`src-tauri/src/rag/hybrid.rs`）：抽样最多 5 个主表片段，
   各取一段 ≥3 字连续文本做**真实 MATCH**，任一样本查不到即判定索引与主表脱节。首版只抽
   一行，会漏判"部分过期"（当时索引里 chunk-1 有、chunk-legacy 没有），已改为多行覆盖检查。
   同时 `fts_index_size` 的文档注释已标注"读穿主表、不可用于判断索引健康"。
3. **自愈入口** `ensure_fts_index`：探针不通过时执行一次 rebuild 并返回是否修复。
   **故意不挂在启动路径**——每次启动都做全量索引扫描不值当；升级路径由 0018 覆盖，
   该函数作为此后任何脱节的兜底（索引被手工清空、未来建表型迁移忘回填）。
4. **保留外部内容表设计**：它不复制正文，符合隐私姿态，因此修法是对账而非改成自带副本的索引表。
5. 回归测试 `fts_rebuild_indexes_rows_that_predate_the_virtual_table` 同时断言失效模式、
   探针判定与自愈结果。Rust `cargo test --lib`：**337 passed / 0 failed**。

### 可选后续

新增一条 lint 测试：凡是创建/改动 FTS 索引的迁移文件，必须包含 `'rebuild'`，防同类问题复发。

## 缺陷二：无空格的自然问句让倒排通道返回空（已实施，见文末「实施结果 · D-407」）

### 现象与根因

`build_match_expression`（`src-tauri/src/rag/hybrid.rs`）对不含空白的查询整串加引号作
FTS5 短语；配合 trigram 分词器，这等价于"文档必须包含这个整串"。于是自然问句必然查不到：

| 查询 | 倒排通道命中 |
|:---|:---|
| `偏振光` | 3 条 |
| `偏振光是什么意思` | 0 条 |
| `偏振光 是什么意思` | 3 条 |

影响：学生用自然问句提问时 BM25 通道静默失效，混合检索退化为纯稠密。评测中的问句形态
即为此现象：纯 BM25 的 Hit@3 从裸词的 0.39 掉到 0.07，混合从 0.89 掉到 0.61。

### 候选方案的实测收益

在问句形态下、24 道"片段金标"题（这些题只能靠倒排通道捞回）上的对照：

| 策略 | 有结果 | Hit@3 | MRR |
|:---|:---|:---|:---|
| a 现状（整串短语） | 0/24 | 0.00 | 0.000 |
| b 剥离问句壳后短语匹配 | 24/24 | 1.00 | 1.000 |
| c 整串 3-gram OR | 24/24 | 1.00 | 1.000 |
| d 剥离问句壳 + 3-gram OR | 24/24 | 1.00 | 1.000 |

（该对照同样受机器标注影响：金标片段含目标词原文，故 b/c/d 都满分。可信的结论只是
"通道从完全无召回变为有召回"。）

### 建议方案（按便宜且精确优先）

1. **剥离问句壳**再匹配，仅对无空白查询生效：`是什么意思 / 是什么 / 什么是 / 怎么算 /
   怎么样 / 请问 / 如何 / 为什么 / 怎么 / 呢 / 吗`。仍是短语匹配，精度不变。
2. **短语无命中时回退为查询 3-gram 的 OR 检索**，交由 BM25 按重合度排序。召回兜底，
   不引入任何依赖，论文"不新增 C++ 外部依赖"的立论不受影响。
3. **长期**：接入真正的中文分词（`jieba-rs`），索引与查询用同一套分词。需改分词器、
   重建索引、随包携带约 5 MB 词典，等于重写论文 §4.2 的依赖论证，建议留待后续版本。

### 明确不推荐

- 把负担推给调用方（要求 PlannerAgent 永远发送空格分隔的关键词）：治不了用户直接输入的问句。
- 长问句直接跳过倒排通道走纯稠密：只是把"静默失效"变成"显式失效"，召回仍然丢失。

### 影响面

改动只影响**当前返回零行**的查询，对现在能工作的短词查询结果不变；但仍属返回结果变更。
落地后需用 `python run_eval.py run --form template` 复跑验证（预期纯 BM25 明显起跳、
混合重新超过稠密），并同步修订论文 §7.8 中该条已知限制的表述。

## 排序问题：融合层把私有片段压在知识库节点之后（已实施，见文末「实施结果 · D-408」）

### 现象

裸词形态、26 道片段金标题：单独 BM25 的 MRR 0.962 / NDCG@5 0.947，融合后降到
MRR 0.635 / NDCG@5 0.680，而 Hit@3 保持 0.9615。即融合**找到了**这些片段，却把它们
排到了节点命中之后。

### 根因

`fuse_rrf` 对未入榜通道以 `K + 1`（=21）名次兜底，于是"倒排第 1 名"与"稠密第 1 名"
得到完全相同的 RRF 分 `1/(60+1) + 1/(60+21)`；并列后按 id 字符串排序，而
`knowledge_node:` / `question:` 恒排在 `private_chunk:` 之前。结果是节点空间在并列时
系统性地压过私有文档空间——与论文 §4.2 "以来源标识区分、互不串扰"的表述有出入。

### 建议方案

1. **去掉平坦兜底**，改回标准 RRF（未召回通道记 0）：这样"两个通道都命中"的文档会自然
   排到"只被一个通道命中"的文档之前。
2. **并列时按来源交替**而非按 id 字典序；或给 top-k 中每个有候选的来源保底若干槽位
   （例如 5 取 2），做成显式的抗饿死规则。
3. 通道加权**不推荐**：会推翻论文"只依赖名次、规避量纲差异"的立论，且需要额外调参论证。

### 配套

评测 harness 目前只落余弦分，未落 RRF 分，导致该问题只能读代码推、无法直接量化。
建议在 `src-tauri/src/rag/eval.rs` 的输出中补 `rrfScore` 字段，再做一次前后对照。

## 实施结果（2026-09-11 实测）

三项修复均已落地，用同一套评测（release 构建，每配置 3000 样本）复跑对照。归档：
修复前 `benchmark-results/20260911-000900-hybrid-retrieval-100q/`，
修复后 `benchmark-results/20260911-004802-hybrid-retrieval-100q/`。

### D-407 问句召回

| 查询形态 | 配置 | 修复前 Hit@3 | 修复后 Hit@3 | 修复前 MRR | 修复后 MRR |
|:---|:---|:---|:---|:---|:---|
| 问句 | 纯 BM25 | 0.07 | **0.39** | 0.070 | 0.390 |
| 问句 | 混合 | 0.61 | **0.86** | 0.575 | 0.755 |
| 裸词 | 纯 BM25 | 0.39 | 0.39 | 0.390 | 0.390 |
| 裸词 | 混合 | 0.89 | 0.87 | 0.748 | 0.761 |

问句形态下"私有片段金标"题的纯 BM25 从 **0/26 命中（MRR 0.000）** 变为 **25/26（MRR 0.9615）**：
倒排通道对该类查询由完全失效恢复到与单通道上限持平；裸词形态结果不变，验证了三阶段召回
"后两阶段仅在前一阶段返回空集时生效"这一约束。

注：本批 100 题不含长叙述句，**3-gram 兜底阶段未被触发**，其行为由单元测试
`trigram_fallback_recalls_when_phrase_misses` 覆盖，未体现在本次聚合指标中。

### D-408 融合并列偏置

| 来源空间 | 配置 | 修复前 MRR | 修复后 MRR | 修复前 NDCG@5 | 修复后 NDCG@5 |
|:---|:---|:---|:---|:---|:---|
| 私有片段 | 纯 BM25 | 0.9615 | 0.9615 | 0.9467 | 0.9467 |
| 私有片段 | 混合 | 0.635 | **0.9615** | 0.680 | 0.862 |
| 知识库节点 | 纯稠密 | 0.7883 | 0.7883 | 0.6879 | 0.6879 |
| 知识库节点 | 混合 | 0.7883 | 0.6903 | 0.6879 | 0.6697 |

私有片段的融合后 MRR 完全恢复到单通道水平（0.635 → 0.9615），字典序偏置消除。
**代价在节点侧**：知识库节点融合后 MRR 由 0.788 降至 0.690、Hit@3 由 0.865 降至 0.838——
奇数名次现在让倒排通道先出，节点曝光整体后移一位。整体是**公平性再平衡而非净增益**
（裸词总体 Hit@3 0.89 → 0.87，MRR 0.748 → 0.761）。

### 时延

| 配置 | 修复前均值 | 修复后均值 | 说明 |
|:---|:---|:---|:---|
| 纯 BM25 | 0.121 ms | 0.204 ms | 未命中时多一次兜底查询；绝对量仍可忽略 |
| 纯稠密 | 2.432 ms | 2.099 ms | 本次未改动（测量波动） |
| 混合 | 2.596 ms | 2.397 ms | 融合层、交替与来源配额无额外开销 |

### 验收

- Rust `cargo test --lib`：**342 passed / 0 failed**（新增 5 项：问句外壳剥离、问句召回回归、
  3-gram 兜底、并列交替、来源配额）。
- 来源配额 `PER_SOURCE_FLOOR=2` 在当前语料下**不是**生效主因（两通道候选数对称，交替本身
  已保证两侧都进 Top-K）；它作为显式抗饿死保证覆盖候选数不对称的场景，由
  `source_quota_reserves_slots_for_each_source` 直接验证机制。
- 论文 v5 已同步：§4.2 融合层改为标准 RRF + 名次奇偶交替 + 每源保底槽位，并新增
  「中文问句的召回处理」段描述三阶段召回；§7.8 移除该条已修复的已知限制。
  `docs/open-decisions.md` 的 D-407、D-408 置为 `decided`。
